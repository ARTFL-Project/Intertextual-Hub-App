# intertextual-hub — the application dependency set.
#
# Verified end to end by T1 on 2026-09-22 in a throwaway ubuntu:26.04 container against
# uv-managed CPython 3.8.20, including that the three version-coupled data artifacts load
# and that the spaCy lemmatiser produces byte-identical output to the running container.
# See ../docker_containers_update/intertextual-hub/MIGRATION.md 3.6.
#
# CPython 3.8 is deliberate and it is an EOL interpreter. 3.9 is reachable but not as a
# packaging change: it needs gensim 4, which removes the .wv.vocab API explore_words.py
# calls and does not cleanly migrate the deployed word2vec models. The base OS, Apache,
# OpenSSL and the system libraries all move to a supported 26.04 regardless, which is
# where the security argument for this migration actually lives.
#
# This is the FULL resolved set, not only the direct pins. spaCy's helper libraries
# (catalogue, cymem, murmurhash, preshed, srsly, wasabi, thinc) are tightly coupled and
# version skew between them is exactly where this stack breaks. Pin what was tested.
#
# THREE THINGS THIS FILE CANNOT EXPRESS, all handled in the Dockerfile:
#   1. fr_core_news_lg==2.3.0 comes from a spacy-models GitHub release, not PyPI.
#   2. spacy/data/fr must be symlinked to the model package. text_preprocessing maps
#      "french" -> "fr" and calls spacy.load("fr"), which is a spaCy 2.x shortcut and not
#      a package name. Without the link the Hub app dies at import with OSError E050.
#   3. text_preprocessing is an ARTFL package and is not on PyPI at all.
#
# Deliberate departures from what is deployed, and why:
#   smart-open       4.0.1  -> 4.1.2   4.0.1 declares python_requires ">=3.6.*", which is
#                                      not a valid specifier; modern setuptools refuses to
#                                      build it. gensim 3.8.3 asks only for >=1.8.1.
#   python-Levenshtein 0.12.0 -> 0.12.1  0.12.0 is yanked from PyPI as insecure.
#   nltk 3.5         DROPPED. Production installs it, and nothing imports it: it enters only
#                    through the embedded topologic's install_requires, which is written for
#                    its MODELLING side (topic_num_evaluator and the `topologic` CLI). This
#                    container only serves. Verified by grepping every .py in the venv - the
#                    one hit is a docstring example inside gensim's deprecated keyedvectors -
#                    and by loading a real .w2v model and the sklearn pickle and confirming
#                    nltk never enters sys.modules. It was 28 of the image's 65 HIGH/CRITICAL
#                    findings, 4 of them CRITICAL, for code that never runs. topologic is
#                    therefore installed with --no-deps; every other entry in its
#                    install_requires is pinned in this file already.
#   python-jose 3.2.0 -> 3.4.0   CVE-2024-33663 (CRITICAL, algorithm confusion) and
#                    CVE-2024-33664. 3.4.0 is the last release for Python 3.8, and it caps
#                    pyasn1 <0.5.0 - see overrides.txt, which keeps pyasn1 at 0.6.4 anyway.
#   ecdsa 0.14.1     -> 0.19.2   CVE-2026-33936. Needed only because python-jose imports it;
#                    this app signs nothing with ECDSA. CVE-2024-23342 remains: it has no
#                    upstream fix, and it is a timing attack on ECDSA signing, which never
#                    happens here.
#   h11 0.11.0       -> 0.16.0   CVE-2025-43859 (CRITICAL, lenient chunked bodies). Not
#                    reachable as deployed: UvicornWorker forces http=httptools, and h11 is
#                    never imported. Upgraded so that choosing the h11 worker stays safe;
#                    tested with uvicorn 0.12.1, and it rejects the CVE's request.
#   joblib 0.17.0    -> 1.4.2    CVE-2022-21797 (CRITICAL, eval in Parallel(pre_dispatch)),
#                    never called with user input here. 1.4.2 is the last release for Python
#                    3.8. Only scikit-learn uses it at runtime (the tf-idf pickle is plain
#                    pickle.load). Tested against the real artifacts under 0.17.0, 1.2.0 and
#                    1.4.2: identical vectorizer output and idf_ hashes, all 415 sklearn
#                    modules import, sklearn's n_jobs path agrees, T1 checks 8/8.
#   pyjwt 1.7.1      DROPPED. Nothing requires it and nothing imports it - a leftover in the
#                    VM's pip freeze, carrying three HIGH findings. The app's JWT library is
#                    python-jose.
#
#   philologic 4.6   NOT listed below: it is not on PyPI either. The Dockerfile builds
#                    its C core and installs its Python package from
#                    ARTFL-Project/PhiloLogic4 at the PhiloLogic-4.6 branch tip.
